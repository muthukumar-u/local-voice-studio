# Maintainer handoff

- Public interfaces: upload page/HTTP API, Python `produce_video`, and `process` CLI. Inputs are video plus narration text or timed SRT/VTT; supplied subtitle text becomes speech and burned captions.
- Provider configuration selects local Kokoro, a compatible speech endpoint, or optional Qwen3-TTS Base reference conditioning in an isolated interpreter. Model/runtime installation and preparation are explicit setup steps.
- Keep this repository application-neutral. Store no consumer names, customer media, external project reports, personal machine paths or application-specific operating notes in tracked files. Runtime inputs, receipts, logs, samples and generated media belong in ignored storage.
- Tests cover contracts, input/timing validation, provider dispatch, job integrity, uploads, restart handling and verified downloads. Check actual provider speech/media separately in the deployment environment; fixtures and dependency detection are not synthesis or listening approval.
- Validated baseline: macOS ARM64/Python 3.12 with the pinned Kokoro assets. Narration, SRT and VTT produce H.264/AAC video through CLI/Python and real HTTP upload/poll/download; burned captions, waveform integrity, output hashes, dimensions, frame rate, duration and delivery loudness have been checked. Timing overflow returns `needs_retime`. Other operating systems and live remote speech services require deployment verification.
- Optional Qwen3-TTS Base reference conditioning has produced a verified voiced video through the configured isolated interpreter using a synthetic reference and exact transcript. This establishes technical generation, normalization and dispatch; human speaker similarity, pronunciation and listening approval remain unverified. The model needs Apple Silicon/Metal and explicit preparation.
- Local setup and runtime requirements are maintained in docs/LOCAL-SETUP.md and docs/PROVIDERS.md. Release changes belong in CHANGELOG.md. Keep credentials and environment-specific support records outside source control.
- Removing consumer records from the current tree does not sanitize older Git commits. Audit existing history before distributing a checkout; history rewriting and remote publication require separate authorization.
