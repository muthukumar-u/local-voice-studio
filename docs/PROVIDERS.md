# Voice providers

All clients use `load_config()` and `providers.create_backend()`. A backend exposes `synthesize(text, speed) -> array('f')`, normalized to finite, nonempty mono PCM at `config.sample_rate`, plus `capabilities` and `provenance`. Capabilities include `reference_audio`, `reference_text_required`, `cloning`, and `speed_control`. `backend_status()` inspects configuration/prerequisites without importing models, calling a speech endpoint, or establishing synthesis readiness. With a configured isolated interpreter, it launches only the bounded metadata status probe. No reference is required for capability/dependency inspection; synthesis still requires audio and transcript for MLX. A facade that will normalize compressed reference audio can use `check_reference=False` for this metadata check before validating the normalized WAV. Existing Kokoro defaults and protocol-v1 jobs remain supported.

| Engine | Configuration | Reference voice | Actual verification |
| --- | --- | --- | --- |
| `kokoro` | Existing `config/explainer.toml` | Unsupported; rejected before model loading | Existing pinned local synthesis path; listening preference still separate |
| `openai_compatible` | `config/openai-compatible.toml` | Unsupported; rejected before any upload | Mocked HTTP transport/WAV contract tests; real loopback server test is included but skipped where sandbox binding is denied; no real remote provider or paid request tested |
| `mlx_audio` | `config/mlx-qwen-base.toml` | Qwen3-TTS **Base** with PCM WAV plus exact transcript | Optional adapter only; no MLX installation, reference-cloning render, or listening test claimed |

## Compatible speech endpoint

`[provider]` accepts `base_url`, `api_key_env`, and `timeout_seconds` (up to 600). The adapter sends JSON `model`, `voice`, `input`, `speed`, and `response_format="wav"` to `<base_url>/audio/speech`. A full endpoint ending in `/audio/speech` is also accepted. This is a specific speech API contract, not universal compatibility with every service. A server that lacks these fields or WAV output needs another adapter.

Use HTTPS for remote servers. HTTP is accepted only for explicit loopback hosts. Credentials are read from the named environment variable; never put the credential itself in TOML or repository files. Redirects are refused. Narration is sent to the configured server, so select that endpoint deliberately. HTTP failures omit server bodies and secret values. Requests and conversion have a bounded timeout; audio responses/normalized PCM are limited to 32 MiB. The adapter checks actual WAV data and rejects malformed, empty, silent, or truncated audio. Different sample rates require configured FFmpeg. Returned audio is not independently transcribed, so PCM validation alone does not establish spoken word coverage or listening quality.

`doctor --model-preflight` and `prepare` make a real speech request for this engine; ordinary doctor does not. A remote success is reported as remote synthesis, not local model installation. The interface does not upload reference samples, create custom voices, or clone a speaker.

## Optional MLX Qwen3-TTS Base

The supported method is `load_model(...).generate(text=..., ref_audio=..., ref_text=...)`. It passes no preset `voice`, because Base reference conditioning and preset speakers are different APIs. Both an existing PCM WAV and its exact transcript are required, either in `[reference]` (`audio`, `text`) or `create_backend(..., reference_audio=..., reference_text=...)` overrides. Relative configuration audio paths resolve against the TOML directory. Output provenance records the reference hash; keep private reference material out of source control and use a speaker recording you are authorized to use.

This adapter requires Apple Silicon macOS, `device="mps"`, a compatible optional `mlx_audio` environment with NumPy, SoundFile, and Hugging Face Hub, and a selected Qwen3-TTS Base model. **Do not install MLX into the locked Kokoro environment**: the model stacks can have conflicting Transformers requirements. Set `[provider].python` to the separate environment's Python executable (relative paths resolve against the TOML directory); the generic facade delegates the whole job through `runtime_worker`, so it does not reload a model for every cue. The example points to `../.clone-venv/bin/python`; that path must actually exist and contain the external package plus compatible MLX dependencies. Ordinary status probes that interpreter with `-m local_voice_studio.runtime_worker --status`, with a ten-second timeout, and uses its reported modules/platform rather than the parent Kokoro interpreter. A missing, nonexecutable, malformed, or nonresponsive worker is a blocker, never a fallback to the parent environment. No worker or MLX installation is established by the profile alone. Default cache-only mode refuses missing models. Explicit download-enabled setup can fetch the selected MLX model into its configured cache; this optional model is not covered by Kokoro's pinned asset manifest.

The adapter uses automatic language selection. It does not implement deterministic speed control: `speed=max_speed=1.0` is required, and an overrun must retime the video instead of silently ignoring a speed change. A declared cloning capability means this adapter accepts reference conditioning; it does not establish that the optional runtime is installed, a sample has been tested, a speaker is faithfully reproduced, or output is approved. Core timing and waveform checks do not prove that all requested words were spoken.
